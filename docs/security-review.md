# 보안·개인정보 검토 — 2026-10-28

## 공개 범위

GitHub에는 소스·개발 설정·테스트·문서만 올립니다. Pages에는 public 폴더만 게시합니다. 업로드 목록은 scripts/security-audit.mjs의 명시적인 허용 목록으로 생성합니다. 실제 일기, SQLite 및 보조 파일, 허브 데이터, 개인 백업, 환경 파일, Firebase/GitHub 자격증명, CLI 로그, QA 자료, 개발 도구와 node_modules는 제외합니다.

원본 로컬 일기장의 data 폴더를 읽거나 복사하지 않았습니다. 원본 일기와 별도 기기에서 저장한 온교실 기록은 자동 이전하지 않습니다. 공개 앱 파일에 사용자 개인 기록을 포함하지 않았습니다.

## 확인한 보호

- Firebase 데이터는 계정 UID별 경로에 분리합니다. 검증된 Google 사용자이면서 경로 소유자여야 읽기·쓰기·삭제가 가능합니다.
- 생성·수정 모두 필드 허용 목록, 타입·길이·태그 개수, 서버 수정 시각을 검사합니다. 생성 시각은 수정할 수 없습니다.
- 계정 삭제 중 사용자 전환과 비동기 저장 경합을 방어합니다. 재인증 후 최소 삭제 차단 표식을 기록하여 새 일기 저장을 규칙 단계에서 막고 남은 기록을 삭제합니다.
- 일기 초안은 탭 메모리만 사용하며 계정 전환·로그아웃 때 지웁니다. 일기 영구 오프라인 캐시는 사용하지 않습니다. 로그인은 브라우저 세션에 유지합니다.
- 사용자 문자열은 HTML 이스케이프합니다. 앱 링크는 HTTP/HTTPS만 허용하며 사용자정보가 포함된 URL은 거부합니다. 새 탭 링크에 noopener/noreferrer를 적용합니다.
- Pages에서 루트 경로에 의존하지 않도록 앱 링크·자산 경로를 상대 경로로 작성했습니다. 허브 설정은 브라우저별이며 웹 서버에 업로드되지 않습니다.
- 로컬 서버는 loopback에 바인딩하고 Host/Origin 검사, 공개 폴더 경로 제한, 입력 크기 제한 및 원자적 파일 저장을 사용합니다.
- CSP는 앱 코드와 필요한 Firebase 인증·데이터 엔드포인트만 허용합니다. GitHub Pages는 사용자 설정 응답 헤더를 지원하지 않으므로 정적 화면에 CSP 메타 태그를 사용합니다.

## 검증 결과

- 일반 Node 테스트: 8개 통과. 에뮬레이터 테스트 1개는 별도 실행했습니다.
- Firestore 에뮬레이터: 무인증 목록·읽기·쓰기, 타인 계정 읽기·쓰기·삭제, 소유권·스키마 오염, 크기·타입 제한 우회, 생성/수정 시각 변조, 미검증 이메일·다른 로그인 제공자, 삭제 표식 이후 경합 저장 차단을 확인했습니다. 정상 생성·조회·수정·삭제도 통과했습니다.
- 독립 코드 검토에서 발견한 중요 문제(500편 목록 제한, 계정 전환 삭제 경합, 가져오기와 삭제 경합, 백업 크기/편수 불일치)를 보완했습니다. 삭제 경합과 큰 백업의 복원 가능성 회귀 테스트가 통과했습니다.
- 개발 의존성 감사에서 발견된 uuid, @opentelemetry/core, @grpc/grpc-js의 알려진 취약점을 패치 버전으로 고정했습니다. 재감사 결과 critical/high/moderate/low 모두 0건입니다. 이는 알려진 취약점 데이터베이스 기준이며 안전성을 보증하지 않습니다.
- 실제 브라우저에서 제외 번호 추첨·소진 안내, 1초 타이머 종료, 대시보드 렌더링을 확인했습니다. 작은 화면 가로 넘침을 수정하고 문서 폭이 뷰포트를 넘지 않음을 확인했습니다.

## 운영 전제와 남은 한계

Firebase 프로젝트 생성은 Google Cloud 최초 이용약관 동의가 필요합니다. 실제 프로젝트의 인증 제공자·승인 도메인·규칙 배포·로그인·실제 저장은 프로젝트 생성 후 별도 확인해야 합니다. 설정이 준비되지 않은 동안 일기장 로그인은 비활성화됩니다.

프로젝트 관리자는 Firebase 관리 도구로 데이터를 볼 수 있으며 종단간 암호화는 제공하지 않습니다. 앱은 로그인 사용자별로 기록을 분리하지만 인터넷에 공개된 Firebase 클라이언트의 남용 방지는 추가 운영 통제(App Check, 사용량 모니터링 등)가 필요한 영역입니다. 결제 계정은 연결하지 않았습니다.

독립 검토의 경미한 잔여 항목: Firestore 규칙의 날짜 검증은 형식만 검사하여 직접 API 클라이언트는 불가능한 날짜를 본인 기록에 넣을 수 있습니다(정상 UI는 실제 날짜를 검증). 기존 온교실의 손상된 브라우저 저장소 복구 동작은 원본과 같습니다. 해당 앱의 백업을 주기적으로 보관하세요.
